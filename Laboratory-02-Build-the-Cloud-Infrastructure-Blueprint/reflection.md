# Mission Reflection

I think networking is the most important cloud infrastructure component because it connects the different parts of the system. Compute and storage resources need a network so users can access them. Without networking, users would not be able to connect to the server or use the services stored in the cloud. Networking also helps protect cloud resources by controlling who can access them.

Linux supports cloud computing by providing an operating system that can run on cloud servers and virtual machines. It is commonly used because it is free, reliable, and easy to manage. In KillerCoda, I used Linux commands such as `lscpu`, `free`, `df`, and `hostname -I` to check the system's CPU, memory, storage, and network information. These commands helped me understand the resources available in the Linux environment.

Technical documentation is important because it helps explain how the infrastructure should be set up before it is created. It can include the needed compute, storage, networking, and operating system resources. Having clear documentation can help prevent mistakes and makes it easier for other people to understand the planned infrastructure.

During this activity, I learned how to use basic Linux commands to check system information. I also learned how to identify compute, storage, networking, and operating system resources. I also learned how to compare similar services from AWS, Azure, and GCP and how to design a simple cloud architecture diagram. Lastly, I improved my skills in writing clear and organized documentation using Markdown.

My GitHub portfolio improved because I added a project that shows what I learned about cloud computing and Linux. The repository contains organized Markdown files about my system findings, cloud components, provider comparison, and reflection. This project shows that I can use Linux commands, understand basic cloud infrastructure, create technical documentation, and organize my work properly on GitHub.
